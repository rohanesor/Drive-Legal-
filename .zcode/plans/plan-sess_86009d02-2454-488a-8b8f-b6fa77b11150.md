## Execution Order & Trade-offs

The plan is sequenced so **every phase is independently safe and the app remains buildable throughout**. Each phase is a discrete unit; if any phase must be paused, prior work is still coherent and committed.

### Phase 1 — Foundation: Aliases, barrel exports, shared types (LOW RISK)
This phase enables everything downstream. No runtime behavior change.

1. **Wire the `@/` alias at runtime** (Babel + Metro). Currently tsconfig defines `@/* → src/*` but it's never used and Babel has no module-resolver, so 98 imports are deep relative paths (`../../store`).
   - Add `babel-plugin-module-resolver` to `frontend/devDependencies` and configure `babel.config.js` with root `['./src']` and alias `{ '@': './' }`.
   - Add matching `tsconfig.json` path (already present: `@/*`).
   - **Trade-off**: Adds 1 dev dependency. Babel cache will be invalidated once on first build.
2. **Create barrel `index.ts` files** for: `store/`, `services/`, `constants/`, `hooks/`, `utils/`, `types/` (types already has one — extend it to also export `AppModeState` which is currently orphaned in `appModeSlice.ts`).
3. **Migrate relative imports → `@/` aliases** across all 38 source files. Mechanical, no logic change.

### Phase 2 — Type Safety (LOW–MEDIUM RISK)
Eliminate `any` and create shared types. Purely additive until the replacements are wired in.

1. **Create `src/types/index.ts` additions**:
   - `NavigationProps` — typed `NativeStackNavigationProp` replacing `{ navigation }: any` on **all 9 screens**.
   - `Severity` = `'low' | 'medium' | 'high'` (currently inline-duplicated in AlertBanner, alerts, map zones).
   - `VoiceState` — consolidate the 3 differently-named-but-identical unions (`'READY'|'LISTENING'|...` in VoiceAssistant, `'IDLE'|'LISTENING'|...` in CarVoice, etc.).
   - `SyncStatus` — de-duplicated from `convexSlice.ts` + `syncService.ts` (currently defined twice, identically).
   - `IconComponent = React.ComponentType<{ size: number; color: string }>` — replacing `Icon: any` in ChallanCalculator's `Violation` interface.
2. **Replace `any` casts**:
   - `catch (e: any)` → `catch (e: { message?: string } | unknown)` with narrowing (5 occurrences: LocationContext, locationService, syncService ×2, VoiceAssistant).
   - `useRef<any>(null)` → `useRef<ReturnType<typeof setTimeout> | null>(null)` (timers), `useRef<Record<string, unknown> | null>` (events).
   - `(result as any).response_text` in ChatScreen → extend `QueryResult` interface in `pythonBridge.ts` to cover the full response shape (already has partial types; complete them).
   - `(data: any)` in backgroundService event listener → `{ latitude: number; longitude: number; speed?: number; heading?: number }`.
3. **Convex type improvements** (no behavior change):
   - `history.role` → `v.union(v.literal('user'), v.literal('assistant'))`.
   - `confidence` → union literal type.
   - Fix the misleading `upsert` naming in `emergency.ts`/`rules.ts` — these only insert. Rename to `insert`/`insertMany` (query/mutation names change, no data change).
   - **Trade-off**: Renaming convex functions changes their API reference (`api.emergency.upsert` → `api.emergency.insert`). The only caller is `syncService.ts`, which I'll update in the same edit.

### Phase 3 — Code Quality: Duplicates, dead code, god components (MEDIUM RISK)
This is the largest phase. Decomposition is done per-screen, each verified before moving on.

**A. Extract shared logic (HIGH VALUE, LOW RISK):**
1. **`src/services/geo.ts`** — single Haversine `calculateDistance()` (currently duplicated in `emergencyService.ts`, `predictiveEngine.ts`).
2. **`src/hooks/useVoiceAssistant.ts`** — extract the near-identical voice state machine duplicated across `VoiceAssistantScreen` (3 funcs), `CarVoiceScreen` (3 funcs), and `CarDashboardScreen` (3 funcs). This is ~9 functions collapsed into one reusable hook with a config-driven keyword-response map.
3. **`src/services/keywordResponses.ts`** — externalize the hardcoded keyword→response mapping (currently duplicated in VoiceAssistantScreen, CarVoiceScreen, CarDashboardScreen with slightly different text).
4. **`src/hooks/useAnimationLoop.ts`** — proper `Animated.loop` lifecycle that stops on unmount. Fixes the **memory leaks in 6+ files** (Dashboard, Chat, VoiceAssistant, Location, Splash, AppIntroAnimation, CarDashboard).
5. **Remove dead code**:
   - `LocationScreen.TN_DISTRICTS` (38 unused entries) + `handleDistrictSelect` (unused).
   - `ChatScreen.handleVoiceInput` (empty body).
   - `locationService.reverseGeocode` trivial pass-through wrapper.
   - `backgroundService` `removeAllListeners('onZoneAlert')` for an event never subscribed.
   - `SettingsScreen.navigation` prop (received, never used).
6. **De-duplicate state data**: `locationService.STATE_MAP` → use `constants/states.ts` `STATES` (the file even imports STATES but maintains its own redundant map).

**B. Decompose god components (FULL RESTRUCTURE — per user decision):**
